# 仓库审计与文档结构

## 先取得依据

确定工作目录、分支和未提交内容。把受影响路径、适用指令与已有资料连起来。跨模块时追踪生产者、消费者和兼容面。需要修改时，先处理同一文件的已有工作和远端差异，遵循项目的分支协作规则。

| 核实的问题 | 可核查的依据 | 优先维护的位置 |
| --- | --- | --- |
| 谁拥有模块和数据，运行时如何装配 | 依赖声明、构建配置、装配入口、存储模型 | 现有架构、数据模型或模块文档 |
| 调用者能依赖什么 | 实际签名、所有相关消费者、错误与兼容性测试 | 现有接口或契约文档 |
| 为什么保留某项设计 | 决策记录、历史差异及当前实现 | 既有 ADR 或其他决策记录 |
| 哪些版本与验证适用 | 构建与发布元数据、发行产物、对应验证记录 | 构建指南、发布记录、现状索引 |
| 维护者从哪里开始 | 根与局部规则、常用入口、权限与副作用 | 根任务指引或最靠近问题的局部指令 |

为重要冲突记下具体文件或符号、对应版本和影响。对标注了时间的历史计划，要区分当时的正确描述与现行承诺。若实现只完成部分迁移，记录已生效范围、现有兼容路径与待决事项。确认活动文档过时后，记录发现及受影响入口。仅在本次任务已获授权修订时，更新授权范围内的正文与入口。

## 选择层级

根入口回答常见任务去哪读或验证。例如，接口变更指向消费者与契约；数据迁移指向所有权、版本、清理边界与定向测试。沿用现有名称和索引，只有新增内容明显超出现有入口的职责时才加文件。

局部指令中的一条规则应让目标目录的工作发生具体变化，例如必须核对迁移前的持久化格式或某个关键消费者。规则可放在公共父级时由父级维护。保留旧指令的必要历史时，确认归档位置、可公开范围和原链接语境。

写追溯性的决策记录时标明记录日期，以实际已有决定和证据为基础。把后续分析的备选方案标为本次分析。决策被替代时，相互链接旧记录和新记录。

## 核查 Agent 加载

分别记录官方或安装包声明、当前客户端与配置、当前会话实际加载的证据。实际加载需确定会话的工作目录、触发动作和规则来源。用户消息提供的规则、手动读取、CLI 帮助各自记录为观察到的证据。

当自动发现未经验证时，显式读取根规则，再沿受影响路径读取局部规则，之后按任务查阅普通文档。需兼容其他客户端时，先核对其实际发现与优先级；兼容入口优先引用同一份规则源。仅在任务需要且获授权时启动新会话或调整配置进行验证。
