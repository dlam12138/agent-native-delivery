# 验证与交接

## 让结论对应证据

检查本轮变更的文档与指令。定位相对链接、锚点及实际源码和配置路径，区分活动引用、历史记录和示例。对已声明的自动化，定位存在的任务或工作流并核查覆盖。只读核验也记录文件、命令与退出状态。

| 已取得的证据 | 可报告的覆盖范围 |
| --- | --- |
| 链接、路径、差异或规则检查 | 实际查过的文档及约束 |
| 任务解析或 dry run | 被解析的任务和计划步骤 |
| 复用缓存结果 | 具体复用的结果与输入版本 |
| Mock、单测或集成测试 | 本轮实际执行的用例、依赖和环境 |
| 设备、真实服务或用户验收 | 对应产物、环境、执行的业务步骤和有权确认的结果 |
| 提交、推送或发布 | 实际核对过的分支、提交、发布地址和产物 |

对无法完成的检查，记录原因和剩余风险。真实服务的读写、身份校验、状态落库等按任务所需逐项确认。涉及凭据或敏感证据时走已有授权渠道，公开报告使用脱敏结果。

## 选择是否分工

按任务难度和已授权工具决定是否委派。简单任务直接处理。复杂范围可交规划角色厘清影响；需查外部事实时交研究角色寻找一手依据；实现由明确的写入者负责。重要变更可由测试与独立审查分别核验证据和语义，审查问题修正后定向复核。

任务说明给每位协作者必要上下文、目标、验收条件、文件范围及权限。独立工作可并行，每个文件只分配一个写入者。协调者检查差异及关键原始证据后再确认完成。

## 交接要点

- 目标与验收标准，以及本次实际完成的范围。
- 文件、产物版本、关键决策和实读依据。
- 检查命令、结果、执行环境、可复核的证据位置。
- 阻塞、待验证事项及相应影响，确有后续任务时记录负责人。

跨会话交接只携带恢复工作需要的信息。用已授权的证据引用代替敏感原始记录，长期规则更新到其所属层级。
